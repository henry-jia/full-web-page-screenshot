## 1. 原始输入

使用者（繁體中文）：「做i18n」。此前於另一 session 的口頭需求：目前所有使用者介面文案硬編碼為繁體中文（popup.html / popup.js / background.js 的狀態與錯誤訊息），希望改用瀏覽器內建 i18n 機制（`_locales` + `browser.i18n.getMessage` / `__MSG_`），預設語言繁體中文，並至少新增英文語系，讓 AMO 上架時能支援多語言列表。

## 2. 用户故事

- US-1: As a non-Chinese-speaking Firefox user, I want the popup, progress, and error messages in my browser locale (English when unsupported), so that I can understand what the capture is doing and why it failed.
- US-2: As the extension owner, I want all user-facing strings centralized in `_locales/<locale>/messages.json`, so that adding a new locale means adding one directory without touching code.
- US-3: As the extension owner, I want the manifest name/description served via `__MSG_` placeholders, so that AMO can present a multi-language listing.

## 3. 验收标准

- [x] AC-1: `manifest.json` 設 `"default_locale": "zh_TW"`，`name` 與 `description` 改用 `__MSG_<key>__` 佔位（由 Node 測試斷言）；Firefox 實機載入無 i18n 錯誤一併留待 AC-4 手動驗證。
- [x] AC-2: popup.html 靜態文案、popup.js 與 background.js 全部使用者可見字串（按鈕、狀態標籤、進度、錯誤訊息）改由 `browser.i18n.getMessage` / `__MSG_` 取得；對 extension/ 目錄 grep 不到殘留的繁體中文硬編碼 UI 字串。
- [x] AC-3: `_locales/zh_TW/messages.json` 與 `_locales/en/messages.json` 的 message key 集合完全一致；Node 測試對所有 `_locales/*/messages.json` 做 key parity 斷言。
- [ ] AC-4: 瀏覽器語系為 en 時 popup 與錯誤訊息顯示英文；語系為 zh-TW（或不支援語系回退預設）時，使用者可見行為與現版完全一致。（需在真實 Firefox 以 en 語系手動驗證）
- [x] AC-5: `npm test` 與 `npm run check` 全綠，且包含新增的 i18n 查表、缺鍵回退與 key parity 的 Node 測試。

## 3.5 深度合约（Depth Contract）— 反浅薄
> verified-build skill 的 Step 1 消费这一节。
- **深模块期望**: 新增獨立 i18n 模組吸收訊息目錄載入、message key 查表、placeholder 代入與缺鍵回退邏輯；popup/background 只以 key 取文案，不感知 locale 解析與回退細節；純函數部分可脫離瀏覽器在 Node 測試。
- **预登记浅薄失败模式**: 只翻 popup 而 background 錯誤訊息仍硬編碼；在 call site 直接寫死英文字串冒充翻譯；把 `__MSG_` 用在 JS 字串裡（僅 manifest/JSON 有效）；兩個 locale 鍵集合不一致導致某語系顯示空白；用字串拼接寫死語序使翻譯無法調整（應用 `$1` placeholder）；漏掉動態組裝的訊息（如含段數、尺寸的完成訊息）仍為硬編碼模板。
- **不变量**: `default_locale` 恆為 `zh_TW`；零資料傳輸、零遙測、無新依賴；zh-TW 使用者可見行為與現版完全一致；缺鍵時 fail-soft 回退預設語系文案，不得拋錯或顯示空白；message key 為英文 snake_case。

## 4. 范围边界

### In Scope
- 新增 `_locales/zh_TW/` 與 `_locales/en/` 的 `messages.json`。
- `manifest.json` 加入 `default_locale` 並將 name/description 改為 `__MSG_`。
- popup.html / popup.js / background.js 全部使用者可見字串遷移至 i18n；含動態訊息的 placeholder 化。
- 瀏覽器無關的 i18n 查表/回退邏輯放獨立模組並以 Node 測試覆蓋（key parity、查表、缺鍵回退）。
- 更新 CLAUDE.md 的「User-facing text is Traditional Chinese」規則與相關文件，改述為 i18n 架構。

### Out of Scope
- zh_TW / en 以外的語系（ja、zh-CN 等）——機制建好後另立需求逐個新增。
- AMO 商店 listing 文案本身的翻譯（商店側欄位，非套件內容）。
- 既有 README 多語版本（README.ja.md、README.zh-TW.md）的內容維護。
- content-script.js 的錯誤碼字串（英文識別字，非使用者可見文案）。

## 5. 关键约束

- **技术**: Firefox Manifest V2、plain JavaScript（無新依賴）、WebExtension 標準 i18n API、Node.js 20+ 測試；瀏覽器無關邏輯放獨立模組（比照 `capture-plan.js` 模式）。
- **业务**: 預設語言繁體中文；message key 與程式碼識別字用英文；AMO 無資料收集聲明維持成立。
- **非功能性**: 零資料傳輸、零遙測；缺鍵 fail-soft；`npm test` 與 `npm run check` 全綠才算完成。
