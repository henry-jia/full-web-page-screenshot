## 1. 原始輸入

建立一個 Firefox Extension，把目前網頁的所有內容擷取成一張 screenshot，尤其要支援需要捲動的長頁面。

## 2. 使用者故事

- US-1: As a Firefox user, I want to capture the active page's entire scrollable area, so that I can save content that does not fit in one viewport.
- US-2: As a privacy-conscious user, I want capture processing to remain local, so that page content is not disclosed to a remote service.

## 3. 驗收標準

- [ ] AC-1: 使用者在一般 HTTP 或 HTTPS 頁面按下擷取按鈕後，擴充套件下載一張 PNG。
- [ ] AC-2: PNG 覆蓋頁面的完整可捲動寬度與高度，而非只有當前 viewport。
- [ ] AC-3: 多個分段被依正確座標拼接，頁面邊緣的非整除餘數不會造成重複或空白區。
- [ ] AC-4: 固定或黏性定位元素不會在每個垂直分段重複出現。
- [ ] AC-5: 無論擷取成功或失敗，頁面原始捲動位置與擴充套件加入的暫時樣式都會還原。
- [ ] AC-6: Popup 顯示擷取進度、成功結果或可理解的失敗原因，且擷取中不可重複啟動。
- [ ] AC-7: 受 Firefox 限制的頁面或超過安全 Canvas 預算的頁面會明確拒絕，不會下載不完整圖片。
- [ ] AC-8: 擴充套件不執行網路請求、不含遙測，截圖只透過 Firefox Downloads API 儲存到本機。

## 3.5 深度合約（Depth Contract）— 反淺薄

> verified-build skill 的 Step 1 消費這一節。

- **深模組期望**: Capture planner 吸收文件尺寸正規化、viewport 分片、尾端裁切、座標去重與像素預算驗證；background 呼叫方只需依序執行計畫。
- **預登記淺薄失敗模式**: 只呼叫一次 visible-tab capture；只處理垂直方向；用固定延遲但不確認實際捲動；尾端整張疊加造成接縫；失敗時未恢復頁面；超大頁面靜默裁切。
- **不變量**: 不上傳頁面資料；不靜默遺失內容；同一分頁同時最多一個 capture；每次 prepare 必須對應一次 cleanup；輸出尺寸必須與經驗證的完整頁面尺寸一致。

## 4. 範圍邊界

### In Scope

- Firefox desktop 的一般 HTTP/HTTPS 網頁。
- 垂直及水平可捲動頁面。
- 分段擷取、Canvas 拼接、PNG 下載、進度與錯誤狀態。
- 固定與黏性元素去重、捲動位置及暫時樣式還原。

### Out of Scope

- Firefox 內建頁面、Mozilla Add-ons 網站及其他禁止擴充套件注入的頁面。
- PDF viewer 的文件級輸出、跨分頁批次擷取、排程、雲端同步與影像編輯。
- 對影片、動畫、WebGL 或持續變動頁面提供逐像素一致性保證。

## 5. 關鍵約束

- **技術**: Firefox Manifest V2、原生 WebExtension API、無 runtime 第三方依賴。
- **業務**: MVP 優先提供可臨時載入與驗證的完整功能，不進行商店發布。
- **非功能性**: 本機處理、清楚錯誤、鍵盤可用、至少 4.5:1 對比、超大 Canvas fail closed。
